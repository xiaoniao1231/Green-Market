# mall-web → mall-web-vue 页面移植规范（Vue3 + Vite）

## 目标

把 `D:\java\KnockoffQQ03\mall-web\js\pages\*.js`（经典脚本、render()+mount() 模式）逐一移植为
`D:\java\KnockoffQQ03\mall-web-vue\src\views\*.vue`（Vue3 `<script setup>` 组件）。

**页面外观与交互必须与原版完全一致**：模板里保留原版 HTML 字符串中的全部标签、class、id、`data-action` 属性。

## 可用的核心模块（`import xxx from '../core/xxx.js'`）

- `config.js` → `QM_CFG`（API_BASE 默认 `/api`）
- `jwt.js` → `QM_JWT`（check / verify / payloadOf …）
- `mock.js` → `QM_MOCK`（categories / products / byId / byCategory / search / sortProducts / paginate / delay / contacts / chats / flashIds / getFlashEnd …）
- `api.js` → `QM_API`（products.* / cart.* / orders.* / favorites.* / auth.* / chat.* / health，签名与原版一致）
- `store.js` → `QM_STORE`（state / on / emit / user / cart / fav / orders / addr / coupon / chat，签名与原版一致）
- `ui.js` → `QM_UI`（esc / price / sales / timeText / fullTime / artStyle / artHtml / toast / modal / confirmDialog / productCard / emptyState / openLogin / openRegister）
- `viewRefresh.js` → `refreshView()`（原 `QM_ROUTER.refresh()` 的替代，登录成功后重挂载当前页）

以上模块不需要再实现；直接 import 后使用（如 `const { toast } = QM_UI;`）。
`QM_STORE` 是普通对象（非 Vue 响应式），变更后按原版逻辑手动刷新本地 ref / 重渲染。

## 路由兼容对象

```js
import useRouteCompat from '../composables/useRouteCompat.js';
const route = useRouteCompat(); // reactive { name, params: string[], query: object }
```

与原版 `route.params[0]`、`route.query.q` 用法一致，且是响应式的：
`route.value.params[0]`、`route.value.query.q`。

**页面内跳转**用 vue-router（不要 import router 文件，避免循环依赖）：

```js
import { useRouter } from 'vue-router';
const router = useRouter();
router.push('/orders');                 // 原 QM_ROUTER.go('/orders')
router.push('/detail/' + id);           // 原 location.hash = '#/detail/' + id
router.push('/search?q=' + encodeURIComponent(q));
```

## 模板规则

1. 模板 = 原版 `render(route)` 返回的 HTML，逐字保留 class / id / `data-action`。
2. 文本插值 `{{ }}`（Vue 自动转义，替代 `esc()`）；动态 class 用 `:class`。
3. 循环渲染用 `v-for`；商品卡 / 空状态等字符串片段可直接 `v-html`：
   `const cardsHtml = computed(() => list.value.map(p => productCard(p)).join(''));`
   参考已完成的示例：`src/views/CategoryView.vue`、`src/views/SearchView.vue`（务必先读）。
4. `open-product / quick-add-cart / toggle-fav / goto-* / open-login / open-register / logout`
   等 `data-action` 已由 `App.vue` 的全局事件代理处理——**模板里保留属性即可，不要在本组件重复实现**。
   页面特有的 `data-action`（如 `cat-sort`、`search-sort`）按原版逻辑实现，可用 `@click` 或
   根节点事件委托（原版用委托时保持委托也没问题）。
5. 不要在页面里使用 Element Plus 组件（外观必须与原版一致）；`QM_UI.modal/toast` 照常用。

## 逻辑规则

- `mount(view, route)` 的初始化逻辑 → `onMounted()`（或 `onMounted(load)`）。
- 原版通过 `view.querySelector('#xxx')` 取元素：可用模板 ref，也可在 onMounted 里
  `document.getElementById('xxx')`（元素在组件模板内，两种都行）。
- 原版 `unmount()` 里的清理（定时器 / WebSocket / 事件监听）→ `onBeforeUnmount()`。
- 同一组件在不同参数间复用（如 /detail/p01 → /detail/p02）：用 `watch(() => route.value.params[0], ...)`
  或 `watch(q, ...)` 重新加载（参考 SearchView.vue），注意恢复原版「重新挂载」时的状态复位（如排序复位）。
- 页面需要响应 QM_STORE 变化时，用 `QM_STORE.on('cart', fn)` 并在 `onBeforeUnmount` 里解绑
  （返回的 off 函数收集在数组里统一调用），原版没订阅就不要加。
- 原版抛错 / try-catch 的行为保持（如商品不存在 → emptyState）。

## 纪律

- 只允许创建 / 修改你自己负责的这一个 `src/views/*.vue` 文件；不要动其他任何文件。
- 完整读一遍源文件再动手；不确定的细节以源文件为准，宁可逐行照搬也不要"简化"。
- 组件顶部注释注明来源文件（参考 CategoryView.vue 头部注释）。
- 不要运行 npm / vite（依赖尚未安装，由主代理统一构建验证）。
